# Plan 2: finish the standalone static site

## Objective and scope

Complete the outstanding work from `goals/plan.md`: an almost pixel-for-pixel copy of the public site that runs without PHP, a WordPress server, or a database. User comments and site search are **out of scope**: do not implement replacements; remove their controls, submission endpoints, and associated runtime calls where present. Preserve article text and existing historical content unless it is a comment or search interface.

Eliminate or replace runtime PHP and WordPress server calls. Assets generated by WordPress, including CSS and JavaScript stored under `wp-content` or `wp-includes`, may remain if they are static files required for the site; a path name alone is not a server dependency. Download external resources needed for presentation or functionality into the site where possible and authorized. Ordinary outbound hyperlinks to other sites are not resource dependencies: preserve them unless they invoke an excluded feature or a broken WordPress/PHP endpoint.

No production modifications or deployment are authorized by this plan. Preserve the original capture and existing builds; implement transformations reproducibly from the capture, not as undocumented edits to a build. Do not assume a host or silently replace an unavailable third-party resource without documenting the change. Ask the owner for source material or permission when necessary.

**Acceptance criteria:**

- No PHP, WordPress server, or database is needed; no runtime requests to WordPress/PHP endpoints occur.
- No search or comment UI or submission behavior remains.
- Required rendering assets are local and work with external network access blocked. Any resource that cannot legally or technically be localized is a documented blocker, not a silently accepted dependency.
- Internal navigation, carousel controls, mobile menu, representative articles, and archives work; static checks find no unexplained failed local requests or incorrect script/style MIME types.
- Homepage and representative article layouts are visually close to the live site on desktop and mobile, with known differences reviewed.
- The result is reproducible from the retained capture, approved asset manifest, and build scripts; the final report records tests, remaining exceptions, and host-specific requirements.

**Risk/recovery:** Browser automation cannot prove every page or visual state. Report coverage and request owner review of the final visual result. If tests reveal a regression, fix the reproducible build and generate another new output; do not overwrite the capture or discard prior builds. Any unavoidable missing content or service-dependent feature requires an explicit owner decision.
